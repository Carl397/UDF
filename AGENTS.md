# UDF release continuity

For release work and continuation requests such as "proceed", "proceed where last", or "continue", first read `deploy/release-progress/STATUS.md`. Resume from the first unfinished item after validating current artifact and environment state. Update that record after meaningful progress, new blockers, or changed verification results, and before ending a session.

Keep completed work, pending work, evidence paths, release identity, and actual deployment/APK outcomes accurate. Do not erase history or reset the progress folder on continuation. Do not repeat passed checks unless their inputs changed. A continuation request does not waive unresolved blockers or required approvals. Never store credentials, tokens, private keys, or personal data in the progress record.
